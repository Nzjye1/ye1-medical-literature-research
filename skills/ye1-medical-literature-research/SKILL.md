# Ye1 医学文献调研

帮助医生系统了解具体医学或科研问题，比较已有研究、分歧与不足，留下可复用的文献和证据记录。用自然语言确定问题，默认中文交流；文献原题和来源保持真实。优先理解医生的临床问题、用途和关注的人群、干预或暴露、比较、结局、研究类型；需要扩大或缩小范围时说明采用的边界。用户已有资料或指定数据库时遵从。

本 Skill 是独立功能；也可根据当前医生目标，在宿主实际可用时接收写作、检查或返修的文献需求。沿用现有研究问题、资料和已有文献，针对需要补查的问题检索、筛选、寻找可用全文，再将文献及实际可支持的论述带回原稿；不强制扩展成完整专题报告。它不代写综述或论文。不能假设其他 Skill 已安装或宿主支持自动调用。

用于文章任务时，沿用本次研究问题和已提供资料，记录检索或阅读来源与实际范围；区分外部文献和医生自己的稿件，只有归属有依据时才把结果关联到具体文章。不要求先创建项目总表或重复提供已有信息。

需要运行本包 Python 脚本时，Agent 优先使用 Python 3.13，已有经验证兼容的环境可直接复用；缺少环境或依赖时按宿主权限自行准备。不让医生选择版本、安装软件或输入命令；确有无法自行处理的授权或网络限制时再简短说明。

## 实际检索

- 使用实际可用的医学数据库、联网或学术工具；医学问题优先考虑 PubMed，并按问题补充适用数据库、中文来源、指南或合法全文。找同义词、人群、研究类型和主要结局，也查安全性、相反结果及近期进展；不要依赖相关性排序前几条。
- 研究类型检索不要只依赖 PubMed 文章类型标签：按问题补充题名或摘要中的系统综述、meta-analysis、随机试验等表达，因为相关题录可能尚未或未按预期标引。补充得到的候选仍需判断实际研究类型与相关性。
- PubMed 可使用 [scripts/pubmed_search.py](scripts/pubmed_search.py) 分页取得所选查询的题录与摘要，细节见[检索与筛选](references/retrieval-and-screening.md)。其他可用来源按其真实分页能力处理。先合理设计查询，再判断获取规模；结果过多时协商合理范围或分批，不能把截断假称完整。
- 保存每组实际检索式、时间、来源、匹配数、取回数、分页与错误记录及实际取得的候选。核对分页返回数、唯一标识和失败情况；一次查询全部取回，只表示该检索式在当时完整返回，不能推断所有相关研究均已找到。
- 按 PMID、规范化 DOI 等核对重复；同一 DOI 有时对应多个不同 PMID 的独立来信或评论，不能仅凭 DOI 合并。跨文献库可能存在多版本或同研究不同报告，识别研究注册号、试验与亚组或事后分析之间的关系，避免重复计算。检索及书目数据变动时保留回执，无法核实的内容写明未知。

## 文献筛选与阅读

- 说明本次拟回答的问题和筛选尺度，按与人群、干预、设计、结局的相关程度选择证据；需要时先浏览题名，再看摘要或全文。优先同时考虑关键原始研究、适用的系统综述／指南、不同结论及安全性研究。
- 在候选表中逐篇记录实际完成的判断、理由与阅读范围：纳入重点、背景、排除、待复核或待筛选；一个都不要把未看过的候选伪装成已筛选。使用 [scripts/screen_queue.py](scripts/screen_queue.py) 可将人工或本次 Agent 的明确决策写成表格；它不代替判断，也不会自动排除文献。研究设计或相关性不确定时保留待复核。
- 阅读实际可得的摘要或合法全文，区分题录、题名、摘要、全文部分和全文；下载 PDF 不等于读完。核对所用文献题名、作者、年份、期刊、PMID/DOI、出版状态和相关更正／撤稿信息；信息不全时注明，不能从检索结果推断每篇均无问题。
- 按读到的内容提取人群、设计、主要结果和限制；区分临床硬结局与替代指标、相关性与因果、亚组与总体。系统综述可能与原试验重叠，不能加总成独立样本。

## 轻量质量自查

- 查找实际可获得、适合本问题的一份相关综述、指南或代表性研究，检查其提到的关键研究是否已出现在本次候选或报告中。先对齐人群、干预、结局和时间范围；范围不同的论文可作为背景或待讨论线索，不直接判为漏检。发现明确相关但未找到的文献时，核验身份与来源，按需补查并记录结果；来源本身也可能有遗漏或过时，不能据此声称已查全。无合适参考时如实说明，不强制使用外部商业工具。
- 回查支撑重要结论的原文或摘要，确认研究对象、比较、关键数字、结局和方向相符；在报告中给出对应来源及实际阅读范围。对于无法核实、证据不一致或仅凭摘要不能判断的内容，写明待核和限制。
- 简短告诉医生核对了什么、发现了什么可能遗漏或范围差异，以及仍未覆盖的来源。仅有一次检索全部取回或某篇综述的少量参考文献命中，不能推断整个领域的召回率。自查以帮助理解问题为目标，不要求每次调研做完整系统综述或独立测评。

## 交付

先回答医生的问题，再梳理主要证据、不同研究之间的分歧、安全性与未知之处。对关键结论给出直接可打开的来源；有用时列出研究人群、设计、结果和局限的对照。说明实际筛选和阅读程度、未查的来源及可能遗漏。不要把这份专题调研称为完整系统综述或直接作为个体治疗建议。

默认按下述本地文献库保存医生可读报告、检索回执和候选／筛选记录，方便后续继续研究。用户指定位置时遵从，不覆盖已有记录。无法联网时可基于已有文献做有限整理，但说明在线检索未完成。

## 本地文献库

- 无需 Zotero。已有文献库优先；否则默认使用当前用户文档目录下的“医学文献库”，每个研究方向独立一个文件夹；无法访问该目录时使用当前持久工作区并告知实际路径。按 [本地文献库说明](references/local-library.md) 使用 [scripts/local_library.py](scripts/local_library.py) 建立主题、保存文献题录和筛选状态、生成可点击目录。保留文献 PMID 或 DOI、原始来源与调研报告；个人笔记和旧报告不覆盖。
- 为主题中未排除的记录，包括重点、背景、待复核及待筛选，尝试保存合法可获取的全文；数量较大时分批并记录尚未尝试的条目。脚本可从 PMC 官方开放数据集保存 PDF，若无 PDF 则保存可用的全文文本或 XML；其他合法开放来源或用户有权提供的全文可另行查找、导入。保留来源、版本及许可；下载失败、未查到及无 PMCID 不等于不存在其他可获取版本。下载不等于阅读，未取得的文献仍保留题录与来源。
- 对 PMC 未取得的候选，可用 [scripts/find_fulltext_links.py](scripts/find_fulltext_links.py) 按公开 PMID／DOI 查 Europe PMC 记录中的全文链接及可用状态；链接只是线索，须确认身份、实际访问与出版版本。工具用法见[本地文献库说明](references/local-library.md)。依宿主能力继续寻找出版商、开放仓储和用户有权访问的来源；无法取得全文时，可在摘要直接支持的范围内使用真实已发表论文，不得称已读全文或猜测未显示的细节。
- 继续既有研究时先定位原主题目录，阅读该目录中的报告、文献清单和追踪状态；按 PMID、DOI 或已有 local_id 合并新题录而保留已保存全文和已作筛选判断。DOI 相同但 PMID 不同不自动合并，信息冲突标注复核。向医生提供主题索引和本地全文入口，不假称本地文件会跨设备自动同步。

## Zotero 与持续追踪

- 用户提出文献管理需求时，先识别真实宿主及文库范围。可用 [scripts/zotero_preview.py](scripts/zotero_preview.py) 只读比较本机 Zotero 的 DOI/PMID，或用 [scripts/export_ris.py](scripts/export_ris.py) 为明确选定文献生成 RIS；不自动导入。实际导入前检查选定目标和已有条目，写后回读；未匹配不代表绝无重复。详见 [Zotero 与追踪](references/zotero-and-tracking.md)。
- 医生要求继续追踪既有方向时，可用 [scripts/track_pubmed.py](scripts/track_pubmed.py) 在完整基线上保存主题、已见 PMID 与上次成功时间，并执行增量检索。传入本地主题目录可将结果并入文献库，并可为本次返回且尚无全文的相关题录尝试保存全文；更新失败不得假称文献库已同步。未完整返回不得推进成功游标；区分新发现与新发表，标注变化需要复核。需定期全量重查以减少延迟入库、旧记录变化和索引范围带来的漏检。
- 用户明确要求定时执行时，按实际宿主的调度工具设置研究方向、频率、运行位置和结果交付，测试首轮并保留运行状态；Skill 或手动脚本本身不会建立定时任务或主动推送。不存在的连接、调度、PDF 或真实文库写入都不得声称已完成。
## 根据目标接续 Ye1 能力

文献查证服务于已有写作任务、医生希望继续成稿时，可衔接 Ye1 医学论文写作（`ye1-paper-writing`），带入研究问题、实际文献和阅读范围；只要求文献调研时先交付结果。

这些关联仅在医生的当前目标确实需要时使用，不为了推荐而增加步骤。已明确需要且该能力在当前宿主可用时，直接沿用已授权资料继续；整套提供的能力可用时不要求另装。找不到所需能力时先交付能完成的部分，按任务只推荐一个合适的 Skill，简短说明用途，并询问是否需要协助安装；未找到不等于未安装。医生同意或明确要求后，按宿主权限及可核实的来源协助，不自动下载、安装或更新，不虚构入口或免费状态。患者逐行资料及身份对应表继续留在数据所在电脑，不进入对话或模型工具输出。
